## Actionable code review findings

### P1: distinct operand uses of one value lose their layouts

`lib/Mapping/CoveringSearch.cpp:167-177` still finds a solved layout by workload **value**, not by endpoint port. Two requirements associated with the same value return `nullptr` at `173-174`. The synthesized request consequently carries no consumer layout.

The compiled probe has a plain producer and a consumer reading its value twice: `operand0` requires `t.plain`, `operand1` requires `t.blocked`. Search accepts one Direct connection. Both solved requirements are retained after the overwrite fix, but their constraints disappear at connection synthesis. Preserve port/role identity through layout solutions, endpoint requests and connections; resolve each use independently or reject unsupported conflicts.

### P2: mapped verifier checks names and types, not full selected legality

`lib/Mapping/PlanBinder.cpp:815-820` checks only `rule.matchOp`. It does not re-evaluate rule attribute/port predicates, executor-kind/compute requirements or resolved parameter constraints. Thus a mapped `micro.vector "mul"` annotated with the add rule/bundle is accepted.

`957-984` checks layout parameter container types, not constraints; changing `VW` to four passes even though the AVX2 layout requires eight lanes. Required layout presence at `890-897` is checked by family name, without complete endpoint-role legality.

Recheck the selected rule against actual operation predicates/types and resources, and validate the recorded solved layouts/parameters against the target declaration. Passing membership checks does not establish legality.

### P2: an arbitrary movement stamp bypasses completeness

`lib/Mapping/PlanBinder.cpp:776-781` skips any workload operation with a `micro.value` attribute. The executed probe removes a vector's mapping, adds `micro.value=0 : i64`, and verification succeeds. Restrict this exemption to validated materialized movement operations and validate their connection/route identity. A generic attribute on arbitrary compute must not establish that the op was mapped.

### P2: exact-mode gather choices remain undisclosed

`lib/Mapping/CoveringSearch.cpp:1063` selects the cheapest gather feed without the new unexplored-choice notice applied to ordinary edges and fan-out. A two-producer/two-route API probe reports four alternatives, zero unexplored flag and zero truncation.

Set the restriction flag/notice for gather feeds too, or branch over their alternatives. Full joint route search remains explicitly deferred; this finding concerns inaccurate disclosure in the implemented restricted exact mode.

### P2: shape-independent constraints wrongly require an MMA

`lib/Conversion/MicroMapping/SearchBindingLoader.cpp:282-288` requires an MMA-derived workload shape whenever any constraint exists. `mapping_extent` only needs thread count and machine capacity (`lib/Perf/Legality.cpp:331-348`), yet a valid vector-only candidate is rejected before mapping.

Derive/evaluate only the facts each constraint needs. Support non-MMA workloads, and report unsupported shape-dependent constraints individually rather than blocking all constrained vector/copy kernels.

### P2: materialized transforms disappear from performance analysis

`PlanBinder.cpp:432-442` emits `micro.transform`; its ODS describes real transformation work. `lib/Perf/MicroDAG.cpp` has no handler and falls through zero-cost success at `963-965`. A transform-only kernel reports `operations: {}` and `predicted_cycles: 0`; inserting one between the copy and vector in the standard fixture produces the same perf report as the control.

Represent transform events/cost/storage and propagate producers through their results. This is a current planner/perf fidelity defect, independent of deferred production calibration.

### P2: unsupported offset views lower as identity

`lib/Conversion/MicroToLinalg/MicroToLinalg.cpp:221-225` compares source/result shapes but ignores offsets. A same-shape view with offsets `[1,0]` is accepted and replaced by the source. The surrounding comment promises unsupported windows fail loudly.

Until extract-slice lowering exists, reject nonzero/dynamic offsets; implement bounds-aware slice semantics when supported. Add zero-offset legal controls and unsupported-offset rejection tests.

## Integration gaps after the new work

### Canonical tile materialization and concrete target execution

The new binder handles tensor movements, replicas and transforms with consumer-scoped chains. It still rejects `!micro.tile` at `PlanBinder.cpp:508` and `551` because TileType is not ShapedType. Same-kind concrete memory transfers are rejected at `573`/`603`; distinct nodes of one memory kind are not interchangeable physical storage. Gather/reduce remains reported rather than materialized. Explicit per-output placement, intermediate allocation and dependency-required barrier semantics remain incomplete.

`require-executable=1` is a useful new guarantee that no selected connection was left unmaterialized; it does **not** prove the backend can lower all source operations. Strictly mapped matmul/SwiGLU still fail conversion at structural loops. Keep that distinction clear in the API/docs and acceptance claims.

### Durable target state and emitter handoff

Typed `bundle_parameters` and solved `layout_parameters` now persist, and emitter verification is invoked. Consumer associations are stored in route metadata and used during rewiring. Retire the previous blanket claims that these are absent.

Solved maps/role associations are not fully represented in operation metadata; the verifier checks parameter shape rather than re-solving legality. `MappingTarget.h:35-56` remains verify-only. The generic Micro-to-Linalg bridge dispatches on operation mnemonics and drops placement/layout/bundle state. It does not invoke the selected target emitter or make the selected implementation bundle determine generated code (§19).

### Constraint and binding semantics

Canonical-kind resolution and per-role layout parameters are new and useful. However `SearchSpace.cpp:132-141` returns null for multiple parameters of the same kind; `Legality.cpp:415-417` interprets this as no layout choice and skips `layout_supported`. Role-aware declarations therefore outpace role-aware legality. This finding is source-confirmed, not separately runtime-probed.

The whole kernel's shape comes from its first MMA (`SearchBindingLoader.cpp:235-250`), which does not establish legality for all contractions or recover original workload dimensions from tiled operations. Owner mapping checks hierarchy availability, but does not itself constrain concrete placement; memory-path/pipeline/tail axes are not a complete lowering bridge.

### Compile, tune, execution evidence

The new Micro-to-Linalg bridge supports a useful subset and preserves inferred input/result signatures. Structural loops, MMA/reduction and some vector/window operations remain unsupported. `llk-compile` still has no integrated target mapping/selected-emitter path; supported Micro input is lowered externally through `llk-opt` and then compiled as Linalg.

`llk-tune` still uses synthetic kernel binding/perf sessions, not MappingTarget → CoveringSearch → selected target emission → measurement. `TuningSession.cpp:35-48` also treats unsupported objective metrics as zero; mapping's stricter objective validation has not unified the tuner contract.

The new execution test explicitly does not call the symbol. It therefore demonstrates compile/lookup viability, not correct numerical execution or an ABI that a runtime caller has exercised. A target-selected mapped kernel, numerical invocation, and required GEMM/fused/transform/tile-two-hop/perf-parity chains are still needed (§25.5).

### Performance and calibration

Compute now follows the selected executor's attached engine; route attribution and operation latency identity are much stronger. Keys now include operand/result types, attributes, resolved bundle parameters, layout parameterization and concrete placement. Retire the corresponding old cache-key findings.

Transform events remain omitted. Selected layout/bundle semantics still do not determine all event behavior; `routeClass` is unset for operation lookups and there is no measured connection-cost lookup. Production measurement/calibration/prediction validation remains #51/#52, distinct from these present static-model fidelity defects.
