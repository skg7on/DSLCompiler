## Delivered behavior

`compile_kernel(fn, binding: KernelBinding) -> FrontendProgram` captures the
frozen binding's source/constants into schema-v1 values, operations and regions.
It does not execute the function body. Assignments preserve SSA identities;
recursive arithmetic, comparisons, full slices/new axes, mask expressions and
positional/keyword mask/other/acc operands retain their types and dataflow.
Unknown calls, control flow and invalid operands produce source-located errors.
Nested function indentation is included in original diagnostic columns.

Counted loops retain induction/iter/init/yield records and rank-two f32 dot
accumulators; they are not unrolled or replaced with a single body execution.
Explicit casts retain ordered result ids and rounding metadata. Recognized SiLU
has explicit source expression/approximation semantics; relaxed activation needs
matching numerical permission. Tests compare typed operands and independently
specified types, shapes, attributes and region connections.

Accepted pointer offsets are represented as `address(base, row, col)` using
`row = offset div width` and `col = offset rem width` from the declared compact
rank-two storage. This preserves physical port rank. Whole-domain affine
single-writer/bounds/coverage proof remains PF05. Source-specific cast/activation
facts extend the program numerical contract; callers use that complete contract
when constructing `CompileRequest` options. No numerical permission is inferred
from a tolerance or backend name.

The language module provides finite capture stubs and raises
`outside_frontend_capture` on eager calls. `JitFunction.frontend_ir(binding)`
returns typed metadata; `ttir()` raises `upstream_toolchain_unqualified`.
The retired pseudo-TTIR builder raises `legacy_ir_builder_unavailable`.
Native invocation raises `native_backend_unavailable`.

## Independent review and verified fixes

A fresh independent reviewer ran all 100 tests at the initial implementation
head and found two Important semantic bugs. Both were reproduced before fixing:

- A preexisting induction binding was restored after a loop, silently exposing
  its old value rather than Python's final iteration value. Capture now rejects
  reused/preexisting induction names, including nested reuse, because v1 exposes
  induction arguments only within their region.
- Unary minus used `0 - x`, which changes the sign of floating zero. Literal
  folding now uses exact negation and runtime floating values use the new
  checked `neg` opcode. The finite JSON grammar and Python validator agree;
  regression tests check negative-zero padding, SSA negation, schema validation
  and canonical round trips. Pointer operands to `neg` fail.

The fix pass is recorded in `fix: preserve unary negation and reject stale loop
bindings` (`0c65068`). The full suite passes 104 tests after that pass; the
reference combined suites each pass 88. The native importer must implement or
explicitly reject `neg`, preserving its exact floating sign semantics.

One minor review suggestion is deferred: the `ttir()` error could name the
`frontend_ir(binding)` replacement directly. The method and migration path are
already documented; the error correctly rejects the unqualified TTIR claim.
Native execution, provider adaptation, affine coverage proof and downstream
integer-division realization were outside the reviewed PF04 claim and remain
required in their respective later milestones.

Documentation checker/source-link regressions pass 13 + 1 tests. The strict
Sphinx HTML build succeeds without warnings. Import/undefined-name/unused checks,
formatting, license headers and diff whitespace checks pass for affected files;
unused assignments are intentional in negative source fixtures.

## Capability boundary

This milestone qualifies typed source capture and diagnostics. It does not
qualify an executable backend or numerical kernel result. No MLIR construction,
native invocation, canary result or actual upstream TTIR is claimed. Native
compilation/import, buffer/alias adaptation and execution remain PF05 onwards.
Required frontend execution CI remains PF20; existing CI covers the native
baseline and manual. The parent #203 remains open.
