## Delivered behavior

`python/llk/runtime/_cache.py` adds `CompilationCache(max_entries=128)` and
`CacheInfo(hits, misses, compilations, evictions)`. A lookup identity is the
canonical `CompileRequest` bytes (source, accepted closure/global constants,
concrete tensor signature, constexprs, launch, numerical policy, search bounds
and the target configuration snapshot by *content*) prefixed by a cache schema
and suffixed by the native environment identity. `_ffi.native_environment()` is
queried before every lookup and records the loaded library path, ABI version and
its size/mtime; the compiled artifact records the compiler and host triple under
`report.native_environment`. A SHA-256 digest indexes buckets, but membership is
always decided by comparing the complete identity bytes, so a digest collision
compiles a separate artifact.

Each entry moves through `pending` → `ready` or `failed` under one lock.
Exactly one caller compiles an identity; concurrent callers wait on that entry's
condition and share the result. A failed compilation is discarded before the
exception propagates, so a later call retries instead of reusing a poisoned
entry. `ready` entries form a bounded LRU; eviction drops only the cache's
owning reference.

`python/llk/runtime/_ffi.py` separates executable ownership from a wrapper:
`_ExecutableHandle` refcounts every owning wrapper, and `CompiledKernel` takes
one reference. `CompiledKernel.lease()` retains another reference and returns a
`CompiledKernelLease` (a `CompiledKernel` subclass, exported from `llk`). Closing
a lease releases only its reference, so eviction cannot free an executable an
active lease is invoking. Wrapper locks serialize calls through one wrapper and
make its `close` wait for its own in-flight invocation; the native service keeps
its own serialization. `CompiledKernel` also exposes `frontend_ir`, `llkir`,
`micro_ir` and `asm`, all read from `llk_frontend_inspect_v1` on the actual
handle. `asm` raises `UnsupportedFeatureError` with `inspection_unavailable`.

`lib/Frontend/Compiler.cpp` now reports `inspection_stages` and the artifact's
`native_environment` (`compiler`, `host_triple`) alongside the already-reported
reached `stages`, search counters, selected/reference group counts, plan id and
ABI hash. `CompilationReport` parses those into immutable `inspection_stages`,
`native_counters` and `native_environment` fields. `JitFunction.cache_info()`
returns the per-kernel cache counters.

## Identity coverage

`test_full_identity_covers_every_specialization_input` constructs nine requests
from one canonical add program and asserts nine distinct identities:

| changed input | mechanism |
| --- | --- |
| shape | new `TensorSpec` extents and launch |
| dtype | f16 rewrite of tensors, values, pointer types and the numerical contract |
| constexpr | changed `BLOCK_M`/`BLOCK_N` |
| closure | changed accepted captured constant |
| grid | different `LaunchSpec` |
| numerical policy | `fma=True` in the numerical contract |
| target | different target name |
| target contents | changed machine YAML text in the configuration snapshot |
| native environment / ABI | different environment bytes |

Two native checks supplement the identity test. The same 16×16/8×16 request
invoked twice reports `CacheInfo(hits=1, misses=1, compilations=1,
evictions=0)`; a changed shape and a changed machine-YAML snapshot each compile
a second artifact with a different `native_request_identity`.

Bullets from `test_specialization_cache.py`:

- `test_equal_digest_buckets_keep_full_identities_separate` patches the digest
  to a constant, compiles two unequal identities and asserts two compilations
  and two distinct artifacts.
- `test_eight_concurrent_misses_compile_once` runs eight threads against one
  identity with the leader blocked inside compilation. Exactly one compile
  attempt enters; all eight invocations succeed; `compilations == 1`; every
  lookup is accounted for by `hits + misses == 8`. The hit/miss split is not
  asserted because a caller that arrives after the leader finished is a real
  hit.
- `test_eviction_keeps_an_active_lease_alive` uses `max_entries=1`: insertion
  of a second identity raises `evictions` to 1, drops only the cache's
  reference (`references == 1`, not closed) and the active lease still invokes.
- `test_failed_compilation_is_not_cached_and_can_retry` and
  `test_unusable_compiled_artifact_does_not_poison_the_cache` assert no
  successful entry survives a failure and a clean retry compiles once.
- `test_native_environment_identity_is_queried_before_every_lookup` changes the
  environment between lookups and asserts a second compilation.

## Lifetime evidence

`test_jit_lifetime.py` uses native handles:

- A lease obtained for 16×16/8×16 survives eviction of its cache entry by a
  32×64/32×64 request with `max_entries=1`, then invokes exact `a + b` values.
- Closing a lease and compiling again is a cache hit; the second lease invokes
  correctly, proving the cache's reference, not the closed lease, kept the
  handle alive.
- A close started while `native_invoke` is deliberately blocked does not
  complete until the call is released; the invocation succeeds, the later
  invocation raises `invalid_frontend_handle`, and no deadlock occurs.
- Eight concurrent decorator calls on one kernel (all released from a barrier)
  enter `compile_request` exactly once, all eight write the exact `a + b`
  values, and `compilations == 1`.
- One native compilation feeds three decorator invocations
  (`native_compile` call count 1, `hits == 2`).
- An injected `native_compile` failure raises once, then the next call compiles
  and writes exact values (`compilations == 1`, `misses == 2`).

## Limits

The cache is process-local and per `JitFunction`; disk/object caching and
persisted measured records remain #51/#52 and #161–#164 work. Provider addresses
never enter the identity, and every invocation still validates caller buffers,
so a hit cannot bypass the buffer contract. Selected-target execution was not
run on this arm64 host (the PF08 evidence records the explicit
`native_backend_unavailable` path); this task adds no reference fallback. No
ASan/LSan result is claimed locally; that lane stays with PF20's Linux tooling.
PF09 does not add elementwise tails, Torch/Inductor composition, training or
upstream Triton launch, and closing #220 does not close #203.
